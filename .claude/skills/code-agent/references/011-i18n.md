# 011 - Internationalisation (i18n)

## Purpose

Every visible string is translated, in Portuguese and English, from day one. Decision pending
(AVG-6) for the setup; the rules below apply from the first page.

## Stack

`i18next` + `react-i18next`. Locales: `pt` (default, written in pt-PT, formal register) and
`en`. Formatting with the built-in `Intl` APIs.

## Files

```text
src/shared/i18n/
├── config.ts               init, supported languages, namespaces
├── types.d.ts              typed keys (CustomTypeOptions)
├── format.ts               date/number/duration helpers over Intl
└── locales/
    ├── pt/{common,auth,flights,pilot,errors,landing,admin}.json
    └── en/{common,auth,flights,pilot,errors,landing,admin}.json
```

One namespace per product area, plus `common` (buttons, pagination, validation, states) and
`errors` (API error codes). The `admin` namespace (or several `admin-*`) is loaded only by the
admin entry.

## Key style

- Semantic, by place and meaning, never the sentence: `flights.bookings.emptyTitle`, not
  `"Ainda não tem reservas"`.
- Namespace prefix in `t()` via `useTranslation("flights")` → `t("bookings.emptyTitle")`, or
  explicit `t("common:actions.save")` for another namespace.
- camelCase segments, nested objects in JSON, max 4 levels.
- Errors use the API code verbatim: `errors:BOOKING_SLOT_TAKEN`.
- Enums from the API map to `<area>.<entity>.status.<value>`.

```json
// locales/pt/flights.json
{
  "bookings": {
    "title": "Reservas",
    "new": "Nova reserva",
    "emptyTitle": "Ainda não existem reservas",
    "emptyBody": "As reservas de voos aparecem aqui.",
    "status": { "open": "Aberta", "flown": "Voada", "cancelled": "Cancelada", "expired": "Expirada" }
  }
}
```

## Config (sketch)

```ts
// src/shared/i18n/config.ts
export const SUPPORTED_LANGUAGES = ["pt", "en"] as const
export type Language = (typeof SUPPORTED_LANGUAGES)[number]
export const DEFAULT_LANGUAGE: Language = "pt"
export const INTL_LOCALE: Record<Language, string> = { pt: "pt-PT", en: "en-GB" }

i18n.use(initReactI18next).init({
  lng: detectLanguage(),           // stored choice → navigator.language → "pt"
  fallbackLng: DEFAULT_LANGUAGE,
  supportedLngs: [...SUPPORTED_LANGUAGES],
  defaultNS: "common",
  ns: ["common", "errors"],        // others load with their route
  interpolation: { escapeValue: false }, // React escapes already
  returnNull: false,
  resources,                       // or lazy backend, see below
})
```

`en-GB` vs `en-US` for English formatting is to confirm (aviation users are international;
24-hour time and day-month order suit them). Decision pending (AVG-6).

The language is stored as a UI preference (`flyavg.language`) and, when signed in, saved on the
pilot's profile through the API. On change, set `<html lang>` to the `INTL_LOCALE` value.

### Loading namespaces

Start with bundled `common` and `errors`. Area namespaces load **inside the page's `lazy()`**,
so the page renders only when its strings exist (no raw keys on first paint) and admin strings
never reach the portal bundle:

```ts
// src/portal/routes.tsx
const Bookings = lazy(() =>
  Promise.all([import("./pages/Flights/Bookings"), loadNamespace("flights")]).then(([page]) => page),
)
```

`loadNamespace(ns)` imports `locales/<lng>/<ns>.json` for the current language and calls
`i18n.addResourceBundle`; on language change it loads the namespaces already in use.

## Typed keys

```ts
// src/shared/i18n/types.d.ts
import type pt from "./resources-pt" // object of all pt namespaces
declare module "i18next" {
  interface CustomTypeOptions {
    defaultNS: "common"
    resources: typeof pt
    returnNull: false
  }
}
```

Typing against `pt` makes a missing key a compile error. A CI script checks that `en` has the
same keys as `pt` (no missing, no extra).

## Writing Portuguese

- pt-PT, formal register. Avoid Brazilian forms (`você`, `tela`, `usuário`, `cadastro`): use
  `ecrã`, `utilizador`, `registo`. Prefer impersonal constructions where possible.
- Aviation terms that pilots use in English stay in English where natural (`PIREP`,
  `callsign`, `hub`), consistent across the app.
- No ending full stop on buttons, labels and titles; full stops in sentences.

## Plurals and interpolation

```json
{ "pagination": { "status_one": "Página {{page}} de {{totalPages}} · {{count}} resultado",
                   "status_other": "Página {{page}} de {{totalPages}} · {{count}} resultados" } }
```

Always pass `count` for plurals. Never concatenate translated fragments; one key per sentence
with interpolation. Rich text uses `<Trans>` with named components, never HTML in JSON.

## Dates, times, numbers

```ts
// src/shared/i18n/format.ts
export function formatDateTime(iso: string, language: Language, options?: Intl.DateTimeFormatOptions) {
  return new Intl.DateTimeFormat(INTL_LOCALE[language], { dateStyle: "medium", timeStyle: "short", ...options }).format(new Date(iso))
}
```

- Flight times show **UTC (Zulu)** by default with a `Z` / "UTC" marker; local time only where
  a screen explicitly asks for it. Decision pending (AVG-6).
- Durations (block time, flight hours) as `hh:mm`, not decimals, unless the API says otherwise.
- Numbers with `Intl.NumberFormat` (`1 234,5` in pt-PT); units are translatable (`nm`, `ft`,
  `kg`/`lb` depending on the airline setting).
- Use a `useFormat()` hook that reads the current language, instead of passing it around.

## Rules

1. No string literal rendered to users in `.tsx`, including `aria-label`, `title`, `alt`,
   `placeholder` and toast text. ESLint `i18next/no-literal-string` (or equivalent) in JSX.
2. Every new key is added to `pt` and `en` in the same change.
3. Remove keys that are no longer used.
4. Text from the API that is user content (pilot names, remarks) is shown as is; text the API
   uses to describe errors is not (use the code).
5. Tests render with the real `pt` resources and query by the translated text or by role name.

## Anti-patterns

- Sentences as keys (`t("A carregar...")`).
- `t(\`status.${value}\`)` with values not covered by a type (use the API enum type).
- Building dates with `toLocaleString()` without the app locale.
- Translating inside schemas or constants at module load (the language can change later).
